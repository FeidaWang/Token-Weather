Using Token Weather

Token Weather gives a local Codex chat a weather-style estimate of how full it may be. The public skills-only package is version 1.0.0. Directory publication is being prepared; this documentation does not mean the plugin has been approved or is already available to install from the OpenAI directory.

Getting started

When Token Weather becomes available in the plugin directory, open Codex on your computer, find Token Weather in Plugins, install it and follow Set up. Local weather readings require Python 3.11 or later and access to a supported Codex chat record. ChatGPT in a web browser cannot read those local records.

Once the plugin is installed, open the chat you want to check and ask: "Show the weather for this chat."

To open the single-page display on your computer, ask: "Open my Token Weather page."

The public package gives readings when asked and has no automatic lifecycle hooks or alerts. The separately distributed local package can use alerts after Codex's normal /hooks trust review. Automatic chat moving stays off.

Reading the weather

Clear or Fair means there appears to be room left. Cloudy or Showers means the chat is getting fuller. Storm means it is near the reference limit. Clearing means Codex reported a real shortening event. Unknown means there is not enough verified information for a current reading.

Chat space is an estimate. The history chart shows recent measurements; the five-turn outlook is a rough forecast, and a long tool result can make the chat grow faster than that forecast.

The output tokens per second figure is a whole-turn average that includes tool waits. It is not the model's writing speed. Account usage is a separate snapshot, available only when Codex provides it. Missing or stale measurements are not treated as zero.

Checkpoints

Checkpoints require an already enrolled project workflow. Ask: "Save a checkpoint for this work." The notes can contain your task goal, requirements, decisions and evidence references. Asking for weather does not enrol a workflow or move work to another chat.

Stopping the page and removing local data

Closing the browser tab does not stop the local weather collector. Ask Codex to stop the Token Weather page service for the current chat, or use weather-service stop with that chat's ID.

After stopping its service or workflow writers, remove the confirmed Token Weather data files separately. The default weather directory is ~/.codex/state/token-weather; an enrolled workflow uses the project's .codex/handover/<workflow-id> directory. Custom configuration can change the weather data location. Do not delete unrelated Codex files.

Archiving a chat, deleting a chat or uninstalling the plugin does not automatically remove these separate files. Exported files and browser display preferences also need separate removal. The privacy policy explains the data, retention and controls.

General support

Use GitHub Issues for general questions and bug reports. Issues are public: do not post private chats, unredacted logs, project files or credentials. Read the support information before posting.
