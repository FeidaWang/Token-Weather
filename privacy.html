Token Weather Privacy Policy

Effective date: 11 October 2026

Publisher and contact

Token Weather is published and maintained by Feida Wang, trading as RSI AI as a sole trader. General support is provided through the project's GitHub Issues. GitHub Issues.

Local information used

When you request a weather reading, Token Weather runs a Python helper on your computer. It locates the local Codex record for the specified chat and checks that its chat ID and project match your request. It reads and parses records in that file to extract usage measurements. Records containing message text may be encountered during parsing, but message text is not copied into the weather history cache.

Weather history includes token counts, timestamps, model and reasoning settings, compaction events, account usage limits when present, chat and turn IDs, and local project and record paths, file identifiers and hashes. Token Weather also reads local Codex configuration to obtain relevant model and compaction settings. These values support the weather estimate, recent history, cache ratio and outlook. The normal weather reader uses account information already present in local records; it does not ask for an API key or fetch your account usage from a publisher service.

Optional notes and local display

If you use checkpoints in an enrolled workflow, Token Weather saves your task goal, requirements, decisions, progress, next steps and evidence references. These notes can contain personal or confidential task information. It also stores workflow history, generations, file paths and fingerprints, and local operation timings and outcomes. Evidence verification can read the specific local files referenced by the workflow.

If you request the single-page display, a local HTTP service runs on 127.0.0.1. It stores service settings, process details, a locally generated service control token and logs. It continues collecting readings until stopped, even if you close the browser tab. The page stores its display mode in browser localStorage. Its weather requests stay on the same local server; it contains no external analytics script.

Recipients and host processing

The weather and checkpoint helpers do not send their stored data to a Token Weather publisher server. Their outputs may be returned to your Codex chat, including requested checkpoint content. Processing of chat and tool outputs by OpenAI is governed by the applicable OpenAI policies and your account settings. Files you export, share, sync or back up are also subject to the services you choose.

The publisher does not operate any additional telemetry or external collection of plugin usage or chat data. If you post an issue or comment, GitHub processes your account information and the content you submit. In the public repository, that content is visible to the publisher and other people, including people who are not project maintainers. GitHub also handles requests to the policy and support website. Provider processing is governed by GitHub's service terms and privacy statement; the publisher does not promise Australian-only processing or control over provider-managed backups.

Retention

Weather data is stored by default in $CODEX_HOME/state/token-weather, with ~/.codex as the default Codex home. TOKEN_WEATHER_DATA_DIR can select another location. Weather history keeps at most 400 recent samples per chat. That limit does not impose a time-based deletion period; cache files, service records and logs remain until deleted.

Checkpoint files and generations are stored under your project's .codex/handover/<workflow-id>. They remain until deleted. Exported files and browser display preferences also remain until you remove them. Uninstalling the plugin or expiring a verification result does not delete these files.

Archiving or deleting a Codex chat does not automatically remove these separate Token Weather files. Local data must be removed separately by the user; it has no time-based automatic expiry.

Public GitHub issues and comments are retained as project support history until removed through GitHub's controls. Token Weather does not apply a 30-day automatic deletion rule to them. Closing an issue does not erase its content. GitHub handles service records and backups under its own policies; removal from the repository cannot guarantee deletion of copies other people have already made.

Your controls

You can stop requesting readings and stop the local display service using weather-service stop for the relevant chat. After confirming it is stopped, remove the Token Weather files from the confirmed data directory. Remove a particular workflow's directory after its writers have stopped, and separately remove exports or copies you created. Do not delete unrelated Codex files. Clear site storage for the local page to remove its display preference. Future readings recreate the cache from the original Codex record; deleting Token Weather data does not delete your original Codex chat.

You can ask general questions about local deletion in GitHub Issues without disclosing private data. For removal of an issue or comment, use GitHub's own controls where available, or make a minimal public request identifying the issue or comment. Do not attach identity documents or private records. GitHub repository permissions determine who can remove content. For requests concerning data held by GitHub itself, use GitHub's privacy controls and support.

Public support and website information

General support uses public GitHub Issues. Your GitHub handle, issue or comment text, timestamps and any attachments you choose to post may be visible publicly and are used to discuss the problem and maintain project support history. Do not post full chat records, private project files, unredacted logs, passwords, API keys or identity documents. This project does not offer email support or solicit private support material through public Issues.

The policy and support pages use GitHub hosting, with no publisher-added analytics, contact forms or tracking scripts. GitHub processes website request information under its General Privacy Statement. This is separate from local plugin operation.
